# 회식각 v2 설계 — 결정 마법사

- 작성일: 2026-11-20
- 범위: 1차 출시 (투표방은 2차)
- 사이트: https://www.hoesikgak.com (GitHub Pages)
- 변경 (2026-11-20): 쩝쩝박사 인증과 운영자가 손으로 채우던 검증·영업상태 칸을 없앴다. 운영자 수동 작업 없이 돌아가게 하기 위해서다.

## 1. 목표

지금 회식각은 한 페이지에 필터, 목록, 지도, 탭이 모두 있어서 복잡합니다. 그리고 평가하러 들어올 계기가 없습니다. v2는 이 두 문제를 이렇게 풉니다.

1. **10초 안에 정하기**: 질문 몇 개에 답하면 바로 후보가 나오고 룰렛이 돕니다. (결정 마법사)
2. **평가가 저절로 쌓이기**: 룰렛 결과를 기억해 두었다가 다음 날 "어땠어요?"로 별점을 받습니다.

유지하는 것:
- 룰렛
- 사옥·내 위치 기준 주변 식당 (카카오 검색)
- 별점 평가 (구글 폼 → 시트 "평가" 탭)
- 카카오톡 공유
- 롤링 배너

## 2. 1차 범위

| 넣는 것 | 빼는 것 (2차 이후) |
|---|---|
| 상황 선택 → 조건 → 후보(목록·지도) → 룰렛 → 결과 | 투표방. 버튼 자리만 "준비 중"으로 둔다 |
| 지도 탐색 화면 (비추 필터 포함) | 카카오 로그인. `worker/` 코드는 보관하고 배포하지 않는다 |
| 상세 시트 + 별점·코멘트 입력 | 운영자 화면 |
| 다음 날 "어땠어요?" 카드 | |
| 낮(B)/밤(C) 테마, 룰렛은 항상 밤 색 | |

## 3. 화면과 이동

주소의 해시(`#/…`)로 화면을 바꿉니다. 브라우저 뒤로 가기가 이전 단계로 돌아갑니다.

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 · ① 어떤 회식? | `#/` | 대상이 있으면 맨 위에 다음 날 카드. 시간대에 맞는 상황 세트(점심/저녁)와 "점심 ⇄ 저녁" 전환 링크 |
| ② 조건 | `#/setup` | 인원, 인당 예산, 기준 위치(사옥 프리셋·내 위치), 있으면 좋은 조건(룸·주차·조용함). 상황 프리셋으로 미리 채워진다 |
| ③ 후보 | `#/picks` | 목록 ⇄ 지도 전환. 후보 카드마다 ✕ 빼기. 아래 고정 버튼은 🎡 룰렛 돌리기, 🗳 투표방(비활성) |
| 룰렛 → 결과 | `#/spin` | 항상 밤 색. 결과 카드에 💬 카톡 공유, 📞 예약 전화, 🗺 지도, 🔁 다시, ✕ 빼고 다시 |
| 지도 탐색 | `#/map` | 전체 화면 지도. 별점에 따라 색이 다른 핀, 평가 없는 곳은 회색. 기준 위치 전환, 하단 목록, 비추 필터 |
| 상세 시트 | 겹침 | 가게 정보와 별점·코멘트 입력. 어느 화면에서든 연다 |

- 공통 상단 바: 롤링 배너(얇게), 로고, 🗺 지도, ☀️/🌙 전환
- 마법사 상태는 주소 쿼리에 담는다. 예: `#/picks?s=team&n=8&b=30000-50000&at=보라매&x=123,456`
  - 키: `s` 상황, `n` 인원, `b` 예산, `at` 기준 위치, `w` 있으면 좋은 조건, `x` 뺀 가게의 카카오ID
  - 새로고침해도 유지되고, 링크를 공유하면 같은 후보가 열린다
  - `at=me`는 공유받은 사람의 위치로 다시 잡는다

## 4. 상황 프리셋

| 시간 | 키 | 상황 | 미리 채우는 값 | 순위 가중 |
|---|---|---|---|---|
| 점심 | `quick` | 🍚 빨리 먹고 들어오기 | 인당 ≤1.5만 | 거리 가중 ×3 |
| 점심 | `newbie-lunch` | 🎉 신입 환영 점심 | 5~10명, 2~3만 | 별점 ×1.5, 인원 적합 |
| 점심 | `vip-lunch` | 🤝 손님·임원 점심 | ≥3만, 조용함·룸 | 조용함, 룸 |
| 점심 | `cheap-lunch` | 💸 가성비 | ≤1.5만 | 예산 가중 ×2 |
| 저녁 | `team` | 🍻 팀 회식 | 6~12명, 3~5만 | 업종 고기·곱창 |
| 저녁 | `vip` | 🤫 임원 있는 자리 | ≥5만, 룸·조용함 | 룸, 조용함 |
| 저녁 | `small` | 🍶 소수 술자리 | ≤4명 | 업종 이자카야·해산물·기타(술집) |
| 저녁 | `farewell` | 🎉 환영·송별회 | ≥8명, 룸 | 별점 ×1.5, 룸 |
| 저녁 | `cheap` | 💸 가성비 회식 | ≤3만 | 예산 가중 ×2 |
| 공통 | `any` | 🎲 아무 데나 | 없음 | 가중 없음 |

상황 조건은 걸러내지 않고 순위만 바꾼다. 정보가 빈 가게가 많아서, 걸러내면 후보가 0곳이 되기 쉽다.

## 5. 후보와 룰렛 규칙

**공통 조건 (걸러냄)**
- 기준 위치에서 1.5km 안 (`CONFIG.NEAR_RADIUS`)
- 비추(평균 ≤1점)는 뺀다
- ✕로 뺀 곳은 뺀다

**평가된 가게의 점수** (`situations.js`의 `score(place, cond)`):

| 요소 | 규칙 (기본 가중치, 상황별로 배수 적용) |
|---|---|
| 별점 | 베이지안 평균 `(합 + 3.5×2) / (개수 + 2)` × 10 |
| 거리 | −1 / 150m |
| 예산 | 범위 밖 −20, 정보 없음 −3 |
| 인원 | 적정 인원 안 +10, 밖 −min(15, 차이×2), 정보 없음 0 |
| 상황 업종 | 일치 +8 |
| 있으면 좋은 조건 | 확인된 "있음" +8, 확인된 "없음" −10, 정보 없음 0 (조용함은 "조용" +6, "시끄러움" −10) |
| 비추표 | 비추 표 1개당 −5 |

**후보 목록** (`picks.js`의 `buildPicks(places, nearby, cond)`):
1. 평가된 가게를 점수순으로 정렬한다.
2. 평균 3점 이상(`CONFIG.ROULETTE_MIN`)인 가게가 6곳 미만이면, 카카오 주변 검색 결과로 채운다.
   - 대상: 평가 없음, 상황 업종 일치, 제외 분류 아님
   - 가까운 순으로 🆕 표시를 붙여 넣고, 목록이 최소 8곳이 될 때까지 채운다
3. 평균 3점 미만인 가게(비추 제외)는 목록 아래쪽에만 두고 룰렛에는 넣지 않는다.

**룰렛**
- 목록 상위에서 최대 8칸을 올린다.
- 칸 크기는 모두 같다.
- 후보가 2곳 미만이면 "조건 넓히기" 안내와 함께 ② 조건으로 보낸다.
- 🆕 가게가 걸리면 결과에 "첫 평가의 주인공이 돼줘" 배지를 붙인다.

## 6. 다음 날 카드

- 룰렛 결과가 나오면 브라우저 저장소에 `{카카오ID, 가게 스냅샷, 시각}`을 남긴다.
- 다음 방문 때 결과 시각이 3시간~3일 전이고, 그 가게를 아직 평가하지 않았으면 홈 맨 위에 "○○, 어땠어요?" 카드를 띄운다.
- 카드에서 할 수 있는 것: 별 바로 누르기, 코멘트(선택), "안 갔어요"(기록 삭제)
- 결과 시각이 3일을 넘으면 기록을 지운다.

## 7. 데이터

**읽기**
- 시트 "평가" 탭을 gviz CSV로 읽는다.
- 열은 타임스탬프, 카카오ID, 매장명, 업종, 카카오분류, 주소, 위도, 경도, 별점, 인당예산, 룸, 주차, 소음, 적정인원, 한줄평, 작성자, 기준, 요청ID.
- 집계 규칙은 지금과 같다.
  - 카카오ID로 묶는다.
  - 작성자별로 마지막 평가만 쓴다.
  - 선택 정보는 최빈값, 예산은 중앙값.
  - "문 닫았어요" 신고(한줄평 `[폐업] 문 닫았어요`, 별점 빈칸)가 서로 다른 2명에게서 모이면 뺀다. 주변 검색 결과에서도 뺀다.
- 이관 전(작성자 `legacy-*` 행 없음)이면 옛 폼 응답 시트도 읽어서 합친다.

**쓰기**
- 구글 폼(`CONFIG.RATE_FORM`, 미리 채워진 링크로 칸을 짝짓는다)에 `no-cors`로 POST한다.

**브라우저 저장소**

| 키 | 내용 |
|---|---|
| `hoesik.uid` | 익명 ID |
| `hoesik.mine` | 내 평가 |
| `hoesik.pending` | 반영 대기 평가 (3일) |
| `hoesik.lastSpin` | 다음 날 카드용 룰렛 결과 |
| `hoesik.theme` | 수동 테마와 날짜 |

## 8. 파일 구조 (빌드 없음, ES 모듈)

```
index.html            뼈대와 상단 바, <script type="module" src="js/app.js">
css/base.css          레이아웃·컴포넌트 (CSS 변수만 사용)
css/theme.css         :root[data-theme=day|night] 색 정의
js/config.js          사옥, 시트·폼 주소, 카카오 키, 반경, 기준 점수
js/store.js           저장소 래퍼 (예외 안전)
js/util.js            esc, unesc, 거리 계산, 포맷
js/data.js            시트 읽기·집계·대기 평가 병합 → loadPlaces()
js/kakao.js           SDK 로딩, 지오코딩, nearby(base), search(q, base)
js/situations.js      SITUATIONS, score()   ← 순수 함수
js/picks.js           buildPicks()          ← 순수 함수
js/roulette.js        캔버스 그리기·회전·결과
js/rating.js          입력 폼, 폼 제출, 다음 날 카드 판단 ← 판단 부분은 순수 함수
js/share.js           카카오 공유, 링크 복사
js/theme.js           themeFor(date, saved) ← 순수 함수, applyTheme()
js/router.js          해시 ↔ 상태 직렬화 ← 순수 함수
js/views/home.js · setup.js · picks.js · spin.js · map.js · sheet.js
js/app.js             시작, 라우팅, 공유 상태
tests/*.test.mjs      node --test
```

- 지금 index.html의 집계, 공유, 카카오 검색 코드는 해당 모듈로 옮긴다. 동작은 바꾸지 않는다.
- `tools/`와 `worker/`는 그대로 둔다.
- 테마
  - 기본: 5:00~16:59는 day, 17:00~4:59는 night.
  - 수동으로 바꾸면 그날만 유지한다.
  - 룰렛·결과 화면은 항상 `data-theme=night` 영역 안에 그린다.
  - 점심/저녁 상황 세트는 시간 기준으로 고르고, 테마와는 따로 바꿀 수 있다.

## 9. 오류와 빈 상태

| 상황 | 처리 |
|---|---|
| 시트 읽기 실패 | 안내와 다시 시도 버튼. 🆕 주변 가게만으로 마법사 동작 |
| 카카오 SDK 실패 | 지도 자리에 안내. 목록과 룰렛은 평가된 가게로 동작. 🆕 채우기는 생략 |
| 위치 권한 거부 | 사옥 선택으로 안내 |
| 후보 2곳 미만 | 조건 넓히기 안내 → `#/setup` |
| 폼 제출 실패 | 대기 목록에 남기고, 다음 접속 때 시트에 없으면 다시 보낸다 (1회) |
| 저장소 차단 | 다음 날 카드와 내 평가 기억만 비활성 |

시트·카카오에서 온 문자열은 모두 `esc()`를 거쳐 화면에 넣는다.

## 10. 테스트

- **단위 테스트 (`node --test`)**: `score`, `buildPicks`(🆕 채우기, 3점 미만 제외, 8칸 상한), 집계, `themeFor`, 라우터 직렬화, 다음 날 카드 판단.
- **흐름 테스트 (Playwright)**
  - 카카오 SDK·폼을 가짜로 대신한다.
  - 390px과 1280px 두 크기에서 돌린다.
  - 흐름 1: 상황 → 조건 → 후보(목록·지도) → 룰렛 → 결과 → 공유
  - 흐름 2: 다음 날 카드 → 별점
  - 흐름 3: 지도 탐색 → 상세 → 평가
  - 콘솔 오류가 없어야 한다.

## 11. 2차 메모 (이번에 만들지 않음)

- **투표방**
  - 주소 쿼리(③ 후보 상태)를 그대로 방 정보로 쓴다.
  - 표는 Worker + KV에 저장한다.
  - 상위 3곳으로 룰렛을 돌린다.
- **카카오 로그인**: `worker/`를 배포하고, 폼 대신 Worker가 쓰기를 맡는다.
